# Web V4 工作台界面规格

## 目标

把已上线的网页版改成更接近 `jlu_booking/gui.py` 的工作台。用户明确要求移除左栏“服务场馆”，将“每日自动预约”和“个人中心”并入“功能导航”，让自动预约采用所给 GUI 截图的结构，并重做每日预约、个人中心和管理员页面。页面适配桌面与手机；已上线的预约、安全及账号行为保持不变。

## 用户工作台

左栏保留校徽、校名、四项功能导航和页脚：场地查询、自动预约、每日自动预约、个人中心。没有场馆侧栏或“更多功能”。场馆选择移入查询及预约表单，当前页面的选择只表示该表单的值，不暗示其他页面共享一个全局场馆状态。移动端导航折叠，可用键盘操作。

自动预约页模仿 GUI 的单张预约方案面板：页面标题、当前场馆、项目与日期的块状选择器、同行人验证状态、首选场地、可调整顺序的重点时间、扫描/真实预约模式，末尾清晰的保存按钮。网页版现有任务是在执行日 07:27 进入调度；按钮必须写“保存预约任务”，不能误称“立即启动”。项目/日期块状选择器需要与原生表单值同步；禁用 JavaScript 时原生控件仍可提交。保留既有 CSRF、场馆项目校验、时间优先级和真实预约模式。

每日预约页把“状态与开关”放在第一屏，明确区分“保存配置”和“开启每日执行”两步；配置表单保持与单次自动预约一致的视觉和字段次序。页面说明下一执行日、目标日、今日名额或阻塞原因。关闭时仍沿用已有的未开始任务取消语义，运行中任务不撤回。

个人中心先展示账号与准备状态，再分开呈现 Token、同行人和密码入口，最后是本网页账号的自动/手动预约记录。Token 保持脱敏；不在页面源代码中写入完整 Token 或学工号。记录继续按用户隔离、分页，并沿用现有详情/日志权限。

## 管理工作台

管理员独立使用左栏导航和页头，不混入普通用户工作台。概览首先显示活跃用户、待绑定用户和运行中任务，并提供用户、任务、审计入口。用户表、任务表、详情和审计统一采用清楚的标题、说明、状态徽标和可滚动表格；危险操作仍按现有确认与权限规则。完整 Token 仍只能走现有重新验证和限时显示流程。手机端布局不得横向撑破页面，表格可在自身容器横向滚动。

## 边界与验证

本版仅调整模板、样式和轻量浏览器交互；如需为显示增加只读统计，不能改变调度、预约、数据库或鉴权逻辑。离线测试覆盖四项导航、各表单真实字段和值、状态开关、个人记录隔离、管理员角色隔离。用浏览器检查典型桌面与 390px 手机视口，并运行全套 pytest、隐私检查、compileall、diff check。不得调用真实 JLU 查询或预约接口。
