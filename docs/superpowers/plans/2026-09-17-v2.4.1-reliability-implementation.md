# v2.4.1 Reliability Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prevent stale-candidate request storms, validate Tokens non-destructively, and expose a reliable last-run status.

**Architecture:** Add a candidate lifecycle reconciler to the existing booking loop, split fast-window behavior from bounded salvage behavior, and centralize Token validation in a small shared module. Persist only privacy-safe run status in an atomic JSON file and expose it through a console command.

**Tech Stack:** Python 3.10+, requests, platformdirs, tkinter, pytest

**Spec:** `docs/superpowers/specs/2026-09-17-v2.4.1-reliability-design.md`

## Global Constraints

- Do not add third-party dependencies.
- Do not log Tokens, full request URLs containing Tokens, or full student numbers.
- Preserve the stop-on-unknown-final-submission safeguard.
- Preserve one shared `requests.Session` per automatic run.
- Count candidate disappearance only after a successful query response.
